# Production navigation acceleration

Scope: preserve the existing charts, editing and recovery, ownership, permissions, current-census source truth, routes and admission workflow. This is a bounded product-performance change, not a new TARS structural slice. No database migration, paid resource, scaling change, service worker clinical cache or Entra change.

## Implementation

- A valid existing Entra session can render Home's canonical, effective-user briefing before browser authentication bootstrap completes. The proxy strips any supplied entry hint and sets its own only for authorized Pipeline pages. The server revalidates through `requirePipelineUser`; React memoization is request-render only. Protected HTML is private/no-store. Sign-in, Microsoft callbacks, shared identity APIs, Notes Lab, mock/header authentication and invalid sessions retain their existing paths.
- Home still performs its usual live refresh, acknowledgment revision checks and focus/30-second polling. Leaving Home discards its initial server seed. The server does not invent another briefing projection or cache an authorization decision between operators.
- The same request-validated effective user seeds header identity/role visibility and starts existing directory GETs without waiting for a second browser user read. That live read still refreshes roles; every data endpoint still checks its own current authorization. Unseeded/mock/header entry retains the old user-read-first behavior. Completed heavy-chart preparation is reused without rescheduling imports/state publication on each navigation.
- Core navigation retains its existing immediate imports: the candidate's first lazy mount delayed Calendar/Reports by about 830 ms in browser certification and Workspaces to about 350 ms live, so those splits were rejected without changing the budgets. Heavy chart/workspace imports begin in Home's first idle turn (750 ms maximum wait), immediately on other surfaces. Existing loading/error handling and history navigation remain intact.
- Prepare one likely next workspace from the existing briefing, prioritizing saved work, upcoming work and then assignments. Numeric intent warms only the canonical canvas, never an inferred person match or binary files. Existing 120 ms drive-by delay, two-workspace/one-profile concurrency limits and 3-second canvas/60-second profile TTLs remain. Hidden tabs, Save-Data and 2G connections skip speculative reads.
- Client history and operational links start together after clinical identity/current-resident resolution. Link errors retain the existing partial operational failure instead of losing the clinical chart; history failures retain their original failure behavior. Visibility and identity checks are unchanged.
- Keep broad clinical mutation invalidation: assessment PATCH can repair identity, so a proposed unrelated-profile retention shortcut was rejected. Existing private-draft and navigation-bookkeeping exceptions remain. No extra response parsing or slower save acknowledgments were added.

## Real-browser telemetry

The native browser observer samples 20% of documents and sends at most five batches of twenty enumerated samples through an authenticated, same-origin, 64 KiB-bounded endpoint. It does not retry, renew authentication, write clinical data or hold a clinical request. Non-core routes and read-only demo/practice workspaces produce zero telemetry requests, preserving their no-write contract. Only surface enums, timing/count values and ready/timeout are accepted. IDs, names, raw paths, queries, elements and arbitrary metadata are rejected. Observer failures/unsupported native timing APIs must not affect the application.

`surface_ready` measures observation of the loaded surface's DOM marker, not certified INP, every decoded thumbnail or every future interaction. LCP is native document LCP; long tasks depend on browser support. Cache hit/join/miss counts are document-interval aggregates, attributed to `other`, not per-screen network timings or a prefetch accuracy score. Values are bounded at 60,000; these bounded logs alone cannot establish fleet p95 or geographic/laptop performance. Headless production journeys remain the release's direct workflow measurement.

## Evidence and rollout

Focused executable coverage: `npm run check:instant-navigation`, existing live-loading and directory-prewarm contracts, TypeScript, changed-owner lint, complexity ratchet, production build and headless Home/history/navigation journeys. Normal CI/security/release gates remain required; no instruction, baseline or complexity ceiling is weakened. Another task's tutorial/recovery work is on its own branch and is not overwritten or silently included.

Production baseline at `8398b9fa2f776845a836fa2346f684c0b0fdf04e`, three fresh Chromium contexts, one authenticated owner, 1440×900 and one-second Home dwell: Home 1,353/617/629 ms; first workspace row 132/116/120 ms; first client card 104/146/93 ms; complete 531-client roster from navigation 2,261/1,412/1,218 ms. Complete roster was ready before Clients click in all three, with zero additional directory GETs or API errors. These are bounded samples, not a claim that every operator is instantaneous.

Keep existing production resources and the already-deployed upstream startup/daily 6 AM Pacific source warmup unchanged.
